PLAYBOOK — PROJECT STATUS
=========================

WHAT IT IS
----------
Fantasy sports betting app built for friend groups. Each league has a commissioner who
sets up a season (NFL weekly structure, playoffs, consolation bracket). Members get a
weekly allowance (fake money) and bet on NFL player props (passing yards, rushing yards,
receiving yards, TDs, receptions) and game lines (moneyline, spread, totals). Bets are
locked per-game at kickoff. Weekly head-to-head matchups are won by whoever profits more
that week. Regular season → playoffs → consolation bracket, with a champion at the end.

Stack: Next.js (app router) frontend · Express + Prisma backend · Postgres DB (Prisma hosted)


WHAT'S BUILT
------------
Auth
  - Signup / login with JWT
  - Admin role (isAdmin flag on User)

Leagues
  - Create league (name, weekly allowance, team count)
  - Invite code system (6-char code, copy to clipboard)
  - Join by code (immediate or pending approval)
  - Commissioner can accept/reject join requests, remove members
  - Leave league (pre-season only)
  - Delete league (commissioner if sole member; admin always)

Season structure
  - Commissioner configures: start week, regular season weeks, playoff size, consolation
  - Start season → generates full regular season matchup schedule (round-robin)
  - Playoff bracket (start + advance rounds)
  - Consolation bracket (start + advance rounds)
  - Champion stored on League record, champion banner shown

Betting — props (player stat over/unders)
  - Bet on passing yards, rushing yards, receiving yards, TDs, receptions
  - Over/under direction, stake, -110 default odds
  - One bet per prop per user per league (unique constraint)
  - Bet locked at game kickoff (server-side check on gameDate)

Betting — game lines (moneyline, spread, totals)
  - Moneyline home/away, spread home/away, total over/under
  - Full American odds support
  - Same kickoff lock and uniqueness rules

Parlay slip (DraftKings-style)
  - Add any mix of props and game lines to slip
  - Odds compound, payout pre-calculated
  - Blocks adding opposing sides (e.g. both Chiefs ML and Chiefs spread against)
  - Max parlay legs enforced (commissioner setting)
  - Parlay submitted as single transaction

Bet limits (commissioner settings)
  - Max stake per individual bet
  - Max total bets per week
  - Max parlay legs
  - These are set independently of season structure (can change mid-season)

Data — sync (admin-triggered)
  - SportsGameOdds API: fetches all upcoming NFL games with DraftKings odds/lines/props
    in one call → upserts into DB (POST /sync/week/:weekId)
  - ESPN API (free, no key): fetches game schedule for a week → creates Game records
    (POST /espn/games/:weekId)

Settlement (admin-triggered)
  - ESPN auto-resolve: fetches box scores + final scores from ESPN, evaluates all
    game lines (spread, ML, totals) and props (actual stat vs line), credits/debits
    balances, settles parlay legs, resolves matchups, marks week resolved
    (POST /espn/resolve/:weekId)
  - Manual resolve fallback: admin enters prop results and game line results by hand
    (POST /weeks/:id/resolve)

Admin panel (/admin)
  - Create/delete weeks, create games, create props, add players
  - Trigger ESPN game sync for a week
  - Trigger SportsGameOdds odds sync for a week
  - Trigger ESPN auto-resolve for a week
  - Manual resolve (enter prop values by hand)
  - View and manage all leagues

Frontend pages
  - / — login/signup
  - /leagues — list of joined leagues + join/create
  - /leagues/[id] — league home: standings, matchup, games this week, commissioner panel
  - /leagues/[id]/bet — bet page: game selector, props tab, lines tab, parlay slip
  - /leagues/[id]/history — all picks/gamepicks/parlays with outcomes, cashout
  - /leagues/[id]/leaderboard — full standings with W-L, balance, rank
  - /leagues/[id]/settings — commissioner: season structure + betting limits
  - /admin — full admin panel


WHAT'S MISSING — DEPLOYMENT READY FOR NFL SEASON
-------------------------------------------------
These are blockers or near-blockers for a real live season with real users and real data.

--- CRITICAL ---

1. No deployment infrastructure
   Everything runs locally. Nothing is hosted.
   Need: Vercel (frontend), Railway or Render (backend), production Postgres URL in env.
   Backend .env currently hardcodes local Prisma dev ports (51213/51214).

2. All data ops are manually triggered
   Admin has to manually click buttons to sync odds, sync games, and resolve each week.
   For a real season this is unsustainable and error-prone. Need:
   - Cron job or scheduled task to sync odds every day during the week (or on demand)
   - Cron job to auto-resolve after Monday Night Game ends each week (~11:30pm ET Monday)
   - Auto-create weeks: pre-generate all 18 NFL weeks with correct 2025 season dates
     (currently admin creates weeks one at a time by hand)

3. No automatic week locking at game kickoff
   Individual bet submission is locked per-game at kickoff (server-side gameDate check).
   But Week.locked is a manual admin toggle — admin has to remember to lock the week.
   This is fine as a fallback but a cron that locks the week at the first game kickoff
   each week would prevent the admin burden and any edge-case bet slippage.

4. NFL 2025 season weeks not created yet
   DB has no weeks. Admin must create each week with start/end dates before the season.
   Need: a seed script or admin button that pre-generates NFL 2025 Weeks 1-18 with
   correct dates so the app is ready when season starts.

5. Live game status never updates
   Games show SCHEDULED → FINAL with nothing in between. The "LIVE" status field exists
   on the Game model but nothing ever sets it. No polling, no live score updates.
   Game cards on home page and bet page show final scores (awayScore–homeScore) when
   status=FINAL, but there's no live score display during games.
   Need: either a polling job that hits ESPN scoreboard to update scores/status during
   game hours, or accept that scores only appear after auto-resolve runs.

--- IMPORTANT (not blockers but should ship with season) ---

6. No password reset
   Users who forget their password cannot recover their account. No email flow exists.
   Need: nodemailer or Resend integration, forgot-password page, reset token stored in DB.

7. No display name change after signup
   Display name is set at signup only. No settings page or PATCH /users/me endpoint.
   Simple fix: add settings page at /settings with PATCH /users/me { displayName }.

8. Bet feed — members can't see each other's bets
   No social visibility at all. After a game kicks off, members should be able to see
   who bet what (stake, direction, outcome once settled). Currently all bets are private.
   Need: GET /leagues/:id/feed?weekNumber=N that returns picks/gamePicks/parlays from
   all members, filtered to games that have already kicked off.

9. Member profile / stats page
   No per-member breakdown exists. Standings table shows W-L and balance only.
   Clicking a member does nothing. Need: /leagues/[id]/members/[userId] page with
   win%, ROI, total wagered, biggest win, current streak, best/worst props.

10. Prop hit rates
    No historical over/under context shown. Each prop just shows line + odds.
    Would show: e.g. "Over 62% · 8 games" under the prop line to help users bet.
    Requires querying settled Prop records for same player+statType across past weeks.

11. No weekly recap
    When a week resolves there's no summary card shown. All data exists to generate:
    your record this week, best bet, biggest miss, profit/loss, matchup result, rank change.
    Would appear at top of league home when week is in resolved state.

--- LOWER PRIORITY ---

12. No commissioner balance adjustment tool
    Commissioner can't manually add/subtract balance from a member (makeup for mistakes,
    penalties, bonuses). Needs: PATCH /leagues/:id/members/:memberId/balance { delta, reason }
    and adjustment history shown in member profile.

13. No email / push notifications
    No alerts when: a bet resolves, week locks, matchup resolves. Users have to check the app.

14. No round robins
    User picks N legs, system generates all 2-leg or 3-leg sub-parlays automatically.
    Stake divided across sub-parlays. Reduces variance vs single large parlay.

15. No CSV export
    Commissioner can't export season data (bets, P&L, matchups) for end-of-year recaps.

16. No futures bets
    Season-long props (Mahomes over 4500 passing yards) not tied to a weekly game.
    Requires manual resolution by admin at season end.
