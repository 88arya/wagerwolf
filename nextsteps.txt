Fantasy Betting League System (Structured Spec)

1. Overview
   This system is a fantasy football-style betting platform. There is no draft and no player ownership. Users receive a bankroll and place bets on NFL games and betting lines (moneyline, spread, totals, player props).

Leagues are managed by commissioners. Users join leagues before the season starts. The system runs week by week aligned loosely with the NFL schedule.

2. Roles

Commissioner

* Creates league
* Defines league rules
* Sets number of users and playoff structure
* Defines regular season length and postseason format

User (Player)

* Creates account
* Joins a league
* Receives weekly bankroll allocation
* Places bets during active game windows

3. Pre-Season Flow

Commissioner Actions

* Create league
* Configure rules:

  * Regular season length
  * Playoff size (top X teams)
  * Betting rules (allowed markets, limits, etc.)

User Actions

* Create account
* Join a league

System State

* No matches yet
* No bankroll activity yet

4. Season Structure

The system season mirrors NFL timing but is independent in structure.

Total season length constraint:

* Regular season + playoffs ≤ 18 weeks

5. Weekly Cycle

Each week runs Tuesday to Monday.

Tuesday (Week Reset)

* New week begins
* Previous week schedule is cleared
* New head-to-head matchups are generated
* Betting slate is reset
* Odds feed is refreshed (reset connection to odds API)

Wednesday–Monday (Active Week)

* Users receive weekly bankroll allocation
* Users place bets on upcoming games only
* Betting includes:

  * Moneyline
  * Spread
  * Totals
  * Player props

Game Resolution

* After each NFL game finishes:

  * ESPN API data is used to resolve outcomes
  * Bets are settled immediately after game completion
  * User balances update in real time

Monday Night (Week Close)

* After MNF ends:

  * Week officially closes
  * All remaining unresolved games are finalized
  * League standings update (W/L records)

6. Matchup System (Head-to-Head)

Structure

* Even number of players per league
* Weekly head-to-head matchups between users

Scheduling Logic

* Matchups are generated to maximize unique pairings
* Constraint:

  * A user should not repeat a matchup against another user unless no other valid pairing exists

This behaves like a rotating pairing system rather than fixed divisions.

7. Postseason (Playoffs)

Qualification

* Top X users (defined by commissioner) qualify after regular season

Format

* Head-to-head elimination rounds
* Loser is eliminated each round
* Continues until champion is decided

8. Weekly Bankroll System

* Each user receives a fixed allowance at the start of every week
* Bankroll resets every Tuesday
* No carry-over balance between weeks

Purpose:

* Prevent compounding advantage across weeks
* Force weekly decision-making discipline

9. Data and API Usage

ESPN API

* Used for:

  * Game schedules
  * Live scores
  * Play results
  * Final outcomes

Odds API (external)

* Used for betting lines:

  * Spread
  * Totals
  * Moneyline
  * Player props

Integration pattern

* Pre-game: pull odds and schedule
* In-game: monitor status
* Post-game: resolve bets via ESPN results

10. Core Game Loop Summary

Pre-season:

* Leagues created
* Users join

Each week:

* Tuesday: reset + new matchups + bankroll refresh
* Wednesday–Monday: betting window
* Throughout week: games resolve and bets settle
* Monday night: close week + update standings

Post-season:

* Top users enter playoffs
* Elimination rounds until winner

11. Weekly Scoring and Matchup Resolution

Weekly Result Calculation

* Weekly performance is based only on realized winnings/losses from settled bets
* Open bets do not count toward weekly results
* Weekly score is determined after all Monday night games finish

Head-to-Head Result

* User with higher weekly realized winnings wins the matchup
* Equal winnings result in a tie

Season Standings

* Standings use W-L-T records
* Season rankings are determined primarily by wins

Playoff Seeding Tie-Breakers

1. Head-to-head record

2. Total cumulative season winnings

3. Highest single-week winnings

4. Random selection / coin flip

5. Bankroll and Winnings System

At the start of each week, users receive:

* Available Capital
* Winnings Tracker

Available Capital

* Used to place bets
* Reset to fixed weekly allowance every Tuesday at 12 PM ET
* Does not carry over between weeks

Winnings Tracker

* Tracks realized profit/loss during the week
* Cannot be re-bet
* Used only for matchup scoring and tie-break metrics

Design Goal

* Prevent bankroll snowballing
* Ensure every week starts on equal footing
* Reward betting performance without compounding advantage

13. Betting Rules

Bet Locking

* Bets lock at official game kickoff
* No live betting after kickoff

Allowed Markets

* Moneyline
* Spread
* Totals
* Player props

Cashout

* Cashout may be available before kickoff if odds move
* Cashout value is determined using updated stored odds
* Cashout calculations use internally stored odds snapshots, not direct live API calls

Cancelled/Postponed Games

* If a game is cancelled before settlement:

  * stake is returned to available capital
  * bet marked cancelled/void

14. Arbitrage and Opposite Outcome Restrictions

Users are not allowed to place bets on opposite outcomes within the same market.

Examples of disallowed combinations:

* Team A moneyline + Team B moneyline
* Over 48.5 + Under 48.5
* Player over 2.5 TD + under 2.5 TD

Examples of allowed combinations:

* Team moneyline + player prop
* Spread + total
* Multiple same-direction bets

Purpose

* Prevent guaranteed-profit arbitrage strategies
* Preserve competitive integrity
* Reduce exploitative hedging behavior

15. Matchup Generation System

League Requirements

* League must contain an even number of users

Scheduling Goals (priority order)

1. Maximize unique matchups
2. Minimize repeat opponents
3. Prefer users with similar records facing each other

System Notes

* Users should not replay opponents unless no alternative pairing exists
* Matchups regenerate every Tuesday for the new week
* Schedule behaves similarly to a rotating round-robin system

16. Weekly Timeline

Tuesday 12 PM ET

* New week begins
* Previous schedule removed
* New head-to-head matchups generated
* Available bankroll reset
* Betting slate refreshed
* Odds API refreshed

Tuesday–Monday

* Users place bets on upcoming games only
* Bets settle after games complete
* User winnings update continuously during the week

Monday Night Football End

* Week officially closes immediately after final game concludes
* Matchups finalized
* W-L-T records updated

17. State Concepts

Bet States

* Pending
* Locked
* Active
* Settled
* Cancelled/Void

Week States

* Pre-Week
* Betting Open
* Betting Locked
* In Progress
* Settlement
* Closed

18. Key Design Intent

* No player drafting or roster management
* Pure betting-based fantasy competition
* Weekly reset economy
* Equal starting bankroll each week
* Matchups provide competitive structure on top of betting behavior
* Season standings emphasize consistency rather than cumulative wealth
