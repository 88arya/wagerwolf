CLAUDE THOUGHTS — V0 NEXT STEPS

This is V0. Keep it tight. No auth, no middleware complexity, no validation libraries.
Bare minimum to prove the loop works.

---

ENTITIES + PRISMA MODELS

User
- id, email, name, createdAt
- just an account, no password for V0

League
- id, name, startingBalance (the amount every new member gets), createdAt

Membership
- id, userId, leagueId, balance, createdAt
- this is the core entity — balance lives here not on user
- unique constraint on (userId, leagueId) so you can't join twice

Week
- id, number (1, 2, 3...), startDate, endDate, resolved (bool)
- resolved flips to true when admin settles the week

Game
- id, weekId, homeTeam, awayTeam, gameDate

Player
- id, name, team, position

Prop
- id, gameId, playerId, statType (PASSING_YARDS, RUSHING_YARDS, TDs etc), line (the number), result (null until resolved)
- result is the actual stat outcome, set manually when resolving

Pick
- id, userId, leagueId, propId, direction (OVER or UNDER), stake, outcome (WIN/LOSS/PENDING)
- outcome starts PENDING, gets set on resolution

---

HTTP ROUTES

POST   /users                        create a user
GET    /users/:id                    get user

POST   /leagues                      create a league
GET    /leagues/:id                  get league

POST   /leagues/:id/join             join league → creates Membership with startingBalance
GET    /leagues/:id/leaderboard      members ranked by balance

POST   /weeks                        create a week
GET    /weeks/:id                    get week with its games and props

POST   /games                        create a game for a week
POST   /players                      seed a player
POST   /props                        create a prop for a game

POST   /picks                        user places a bet (needs userId, leagueId, propId, direction, stake)
GET    /picks?userId=&leagueId=      get a user's picks in a league

POST   /weeks/:id/resolve            admin sets prop results, evaluates picks, updates membership balances

---

NOTES

- No auth for V0. userId comes straight from request body.
- No balance validation yet (can go negative, fine for V0).
- resolve route is the only route with real logic: loop picks, compare stake direction to prop result, add/subtract from membership balance.
- Seed data manually via POST routes or a seed script, not a UI.
