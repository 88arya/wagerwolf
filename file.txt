PLAYBOOK — PRODUCTION VISION FOR NFL 2025 SEASON
==================================================

The goal: zero admin involvement once the season starts.
The site syncs its own games, opens and locks betting windows,
settles all bets, and updates standings automatically every week.
No one touches a dashboard. It just runs.

HOSTING & DEPLOYMENT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Frontend — Vercel
  - Next.js deploys to Vercel with zero config
  - Auto-deploys on every push to main branch
  - CDN-distributed globally, no servers to manage
  - Environment variables set in Vercel dashboard
  - Free tier covers a friend-group scale app easily

Backend — Railway (or Render)
  - Express + Prisma app deployed as a persistent server
  - Connects to GitHub repo, auto-deploys on push
  - Runs the startup seed on every boot (idempotent, safe)
  - Stays alive 24/7 — needed for cron jobs and webhooks
  - Railway gives you a managed Postgres too (simpler than a separate DB service)
  - ~$5–10/month for this scale

Alternative: if we outgrow Railway → AWS ECS with Fargate
  - Container-based, scales horizontally
  - More setup but full control over compute
  - Worth it only if user count grows significantly


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
DATABASE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Primary: PostgreSQL via Railway (bundled with backend hosting)
  - Prisma ORM already configured, zero migration needed
  - Railway's managed Postgres handles backups, connection pooling
  - Single DB is fine for this scale (dozens of leagues, hundreds of users)

Alternative: Neon (serverless Postgres)
  - First-class Prisma support, scales to zero when idle
  - Branching for staging environments (dev/prod on separate branches)
  - Better choice if we want the DB separate from the compute layer
  - Free tier is generous

What lives in the database:
  - All user accounts, league configs, memberships, balances
  - Every Week, Game, Player, Prop, GameLine record for the season
  - Every Pick, GamePick, Parlay placed by every member
  - Outcomes after settlement, W-L records, matchup results
  - Chat messages, league feed

What does NOT need to be stored (fetched at runtime):
  - ESPN player headshots — served directly from ESPN CDN
  - Live game scores during games — polled from ESPN on demand
  - Odds during sync — pulled from SportsGameOdds then stored in DB

CRON JOBS — THE AUTOMATION ENGINE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

This is the core of "runs itself." Six recurring jobs cover the full season.

Where crons run: inside the Express backend as node-cron jobs.
Railway keeps the server alive 24/7, so crons fire reliably.
No Lambda, no EventBridge complexity needed at this scale.

─────────────────────────────────────────────
JOB 1 — SEASON BOOTSTRAP (runs once, ~Sep 1)
─────────────────────────────────────────────
Trigger: one-time manual run before Week 1

What it does:
  - Creates all 18 Week records for the 2025 NFL season
  - Pre-populates correct NFL calendar dates for each week
  - 2025 NFL regular season: Sep 4 (Week 1) → Jan 4, 2026 (Week 18)
  - After this, the cron jobs below handle everything automatically

This is the one setup step a human does. Everything after is automated.

─────────────────────────────────────────────────────
JOB 2 — GAME SYNC (every Wednesday 8am ET, weeks 1–18)
─────────────────────────────────────────────────────
Calls: ESPN scoreboard API (free, no key)
Route: internally calls the same logic as POST /espn/games/:weekId

What it does:
  - Pulls the upcoming week's full schedule from ESPN
  - Creates/updates Game records: homeTeam, awayTeam, gameDate, ESPN event ID
  - gameDate is the critical field — it's what auto-locks bets server-side

After this job: the league home page shows "This Week's Games"
and the countdown to bet-lock is live.

─────────────────────────────────────────────────────────────────
JOB 3 — ODDS SYNC (every Thursday 9am ET, weeks 1–18)
─────────────────────────────────────────────────────────────────
Calls: SportsGameOdds API (paid, ~$50–100/month for this usage)
Route: internally calls the same logic as POST /sync/week/:weekId

What it does:
  - Pulls player prop lines for every game this week
  - Pulls game lines: spread, moneyline, total for every game
  - Creates Prop and GameLine records in DB
  - Skips any props/lines that already exist (idempotent)

After this job: the Bet page is fully open with all props and lines.
Members can place bets from Thursday morning until each game kicks off.

Fallback: if SportsGameOdds is down or rate-limited, the fake sync
runs as a backup so the betting window still opens on time.

───────────────────────────────────────────────────────────────────────
JOB 4 — LIVE SCORE POLLING (every 60s during active game windows)
───────────────────────────────────────────────────────────────────────
Calls: ESPN box score / summary API (free)

Active game windows (ET):
  - Thursday:  7:30pm – 11:30pm
  - Sunday:    12:30pm – 11:59pm  (covers 1pm, 4pm, SNF)
  - Monday:    7:30pm – 11:30pm

What it does:
  - For each game in the week where status != FINAL:
    - Calls ESPN summary endpoint for that event ID
    - Updates game.homeScore, game.awayScore, game.status (LIVE/FINAL)
  - Frontend polls a lightweight /games/live endpoint every 30s
    and updates scores on the league home page in real time

Outside game windows: polling stops completely (no unnecessary API calls).

This is what's currently missing — once built, game cards show live scores.

───────────────────────────────────────────────────────────────────────────────
JOB 5 — AUTO-RESOLVE (every Tuesday 6am ET, weeks 1–18)
───────────────────────────────────────────────────────────────────────────────
Calls: ESPN box score API for final stats
Route: internally calls the same logic as POST /espn/resolve/:weekId

What it does:
  1. Fetches final box scores for every game in the week
  2. Reads actual player stat totals (rushing yards, receiving TDs, etc.)
  3. Settles every Pick in the week:
       OVER: actual stat > line → WIN | LOSS
       UNDER: actual stat < line → WIN | LOSS
       Exact line → VOID (stake refunded)
  4. Settles every GamePick:
       Spread, moneyline, total evaluated by standard rules
  5. Settles every Parlay:
       All legs WIN → parlay pays out at compound odds
       Any leg LOSS → whole parlay LOSS
       VOID leg → that leg removed, remaining legs pay out
  6. Updates every member's balance in their league (credits wins, refunds voids)
  7. Calculates each Matchup winner for the week (who profited more)
  8. Updates W-L records and standings
  9. Marks the week as resolved
  10. Triggers settlement notifications (see Notifications below)

After this job: History page shows all WIN/LOSS outcomes,
standings are updated, weekly recap appears on league home.

───────────────────────────────────────────────────────────────────
JOB 6 — ODDS REFRESH (optional, Thursday–Sunday every 4 hours)
───────────────────────────────────────────────────────────────────
Calls: SportsGameOdds API

What it does:
  - Re-syncs any odds that have moved since Thursday morning
  - Only updates lines that haven't been bet on yet (can't change
    the line on an existing pick — that pick's odds are locked at placement)
  - Keeps lines fresh for members who haven't bet yet

This is a nice-to-have, not required for v1.

FULL AUTOMATED WEEK TIMELINE (no one touches anything)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

TUESDAY 6:00am   — Auto-resolve fires, settles previous week's bets
TUESDAY 6:10am   — Settlement notifications sent to all members
WEDNESDAY 8:00am — Game sync fires, loads this week's schedule
THURSDAY 9:00am  — Odds sync fires, bet page opens with full lines
THURSDAY 8:20pm  — TNF kicks off, bets on that game auto-lock
SUNDAY 1:00pm    — 1pm games kick off, bets lock
SUNDAY 4:25pm    — 4pm games kick off, bets lock
SUNDAY 8:20pm    — SNF kicks off, bets lock
MONDAY 8:15pm    — MNF kicks off, bets lock
MONDAY ~11:30pm  — MNF ends, all games FINAL in ESPN
TUESDAY 6:00am   — Cycle repeats

BET LOCKING (already works, no changes needed)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Bets lock automatically. Every time a member tries to place a bet,
the server checks: game.gameDate <= now. If yes, the bet is rejected.

No cron needed. No admin click needed. It's purely time-based and
already live in the codebase. Once Job 2 (game sync) populates
correct gameDates, locking is fully automatic.

NOTIFICATIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Email (via Resend — simplest integration, free tier generous)
  - Account created → welcome email
  - Password reset → reset link (already exists, just needs SMTP hooked up)
  - Week settled → "Your bets are in. Here's how you did." summary
  - Week opens → "This week's lines are up. Place your bets."

Push notifications (future — web push via VAPID or a service like OneSignal)
  - Bet settled notification
  - Reminder when betting window is closing (e.g. 1hr before TNF)
  - Matchup result

SMS (Twilio — optional, higher cost, higher open rate)
  - Worth considering for bet settlement and weekly open notifications
  - Members opt in via settings page

Priority order for v1: Email only. Push/SMS in v2.

EXTERNAL SERVICES SUMMARY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Service              Purpose                           Cost
──────────────────   ──────────────────────────────    ──────────────
Vercel               Frontend hosting + CDN            Free
Railway              Backend hosting + Postgres        ~$10/mo
SportsGameOdds       Real prop lines + game odds       ~$50–100/mo
ESPN API             Games, scores, box scores         Free
Resend               Transactional email               Free (3k/mo)
GitHub               Source control + CI/CD            Free

Total estimated monthly cost: ~$60–110/month for a production season.

NOT needed (simpler than you'd think):
  - AWS (Railway handles what we need without the complexity)
  - Redis / caching (DB queries are fast enough at this scale)
  - Separate CDN for images (ESPN CDN serves headshots directly)
  - Message queues (cron jobs are sequential and lightweight enough)
  - Kubernetes / containers (Railway manages this)

If the app grows to hundreds of leagues: add AWS RDS (larger Postgres),
ElastiCache (Redis for hot data like standings/leaderboard), and
move crons to AWS EventBridge + Lambda for reliability guarantees.
