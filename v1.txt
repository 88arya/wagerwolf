PRE-MVP → MVP
no public signup, no odds api, manual lines via admin

─────────────────────────────────────
CRITICAL (app is broken without these)
─────────────────────────────────────

1. PASSWORD HASHING
   passwords stored as plaintext in db right now
   use bcrypt before anyone real uses this

2. AUTH / SESSION TOKENS
   userId is passed in the request body and trusted blindly
   anyone can bet as anyone else
   need JWT on login, token stored in localStorage, sent as Authorization header
   backend verifies token on every protected route

3. BALANCE RESERVATION AT BET TIME
   balance only updates at week resolution
   player with $200 can place 10 bets of $200 each before anything resolves
   fix: deduct stake when bet is placed, refund if week is cancelled
   or: track total pending stakes and reject if balance - pending < new stake

4. BET LOCKING
   nothing prevents bets after a game starts
   admin needs a "lock week" action, or auto-lock per game based on gameDate
   once locked, POST /picks should reject for that week

─────────────────────────────────────
IMPORTANT (mvp feels incomplete without)
─────────────────────────────────────

5. ADMIN PROTECTION
   /admin is publicly accessible right now
   simplest fix: admin password prompt stored in env, checked client-side
   real fix: mark a user as admin in db, check on backend

6. INVITE CODES
   sharing a 25-char cuid to join a league is unusable
   generate a short 6-char alphanumeric code on league creation
   store on League model, join by code instead of id

7. COMMISSIONER CONTROLS
   whoever created the league should be able to:
   - remove a member
   - see league id / invite code
   currently no concept of league ownership at all

8. NEGATIVE BALANCE PROTECTION
   if a player loses everything they go negative, which is a dead account
   decide: floor at 0, or let it go negative and weekly allowance digs them out

─────────────────────────────────────
BEFORE GOING LIVE
─────────────────────────────────────

9. DEPLOYMENT
   app is local only
   frontend: Vercel (free, zero config for Next.js)
   backend: Railway or Render (free tier)
   database: swap prisma dev for Prisma Postgres cloud or Supabase
   update NEXT_PUBLIC_API_URL in frontend env

10. ENV / SECRETS HYGIENE
    JWT_SECRET must be in env, not hardcoded
    DATABASE_URL must be a real hosted connection string in prod
    make sure .env is in .gitignore (it is, verify no secrets ever committed)
